# Моё личное расписание

Персональный цифровой диспетчер: календарь, расписание дня, задачи, контекст,
проекты, контакты, история и Telegram-уведомления. Реализовано по ТЗ
(`ТЗ_Мое личное расписание.docx`) на стеке **Next.js + TypeScript + Tailwind**.

## Два режима работы

Приложение автоматически определяет режим по наличию `.env.local`:

- **Локальный режим (по умолчанию)** — без единой регистрации на сторонних сайтах.
  Данные хранятся во встроенной в Node.js базе SQLite прямо на вашем компьютере
  (файл `.local-data/app.db`). Достаточно `npm install && npm run dev`.
  Ограничения: без Telegram-уведомлений и без доступа с телефона отдельно от
  компьютера (нет облака — некуда телефону подключиться).
- **Облачный режим** — после того как в `.env.local` появятся переменные
  Supabase (см. ниже), приложение при следующем запуске само переключится на
  них: авторизация, доступ с любого устройства, Telegram-напоминания, cron.
  Никаких изменений в коде не требуется — обе версии работают на одной кодовой базе.

## Статус реализации

Все 6 этапов из раздела 83 ТЗ реализованы в объёме MVP+:

- **Этап 1 (ядро)** — авторизация (в облачном режиме), БД, действия, календарь (день/неделя/месяц/год), временная шкала, создание/редактирование, перенос (drag&drop + кнопка), статусы.
- **Этап 2 (интеллектуальная структура)** — контекст, проекты, контакты, дедлайны, результаты, повторения (RRULE + исключения серии), связанные действия.
- **Этап 3 (уведомления)** — reminders (в приложении — в обоих режимах; Telegram — только в облачном), утренний план, вечерний итог, notification service, cron-обработчики.
- **Этап 4 (история)** — журнал изменений, архив (soft delete), глобальный поиск, фильтры, итоги дня.
- **Этап 5 (данные)** — экспорт JSON/CSV/ICS, импорт с проверкой дублей (работает в обоих режимах — так переносятся данные из локального режима в облачный).
- **Этап 6 (AI-ready)** — типы `ParsedActionDraft`, эвристический parser как пример контракта, точка расширения `aiParseNaturalLanguage`.

### Известные ограничения v1

- **Telegram и cron-уведомления недоступны в локальном режиме** — это принципиальное ограничение (некому слать сообщения без публичного сервера), не баг. Вкладка Telegram в настройках скрыта, пока не подключён Supabase.
- **В приложении напоминания** (раздел 48) в локальном режиме показываются, только пока открыта вкладка браузера — клиент опрашивает сервер каждые ~45 секунд. В облачном режиме это дублируется cron-задачами, которые работают даже при закрытом браузере.
- **Offline-очередь** (раздел 54) реализована архитектурно (API-слой изолирован от UI), но локальная очередь изменений на клиенте не встроена; при потере сети запросы сейчас просто завершатся ошибкой с уведомлением.
- **Vercel Cron на бесплатном Hobby-плане** ограничивает cron-задачи одним запуском в сутки. Для напоминаний "по минутам" в облачном режиме нужен либо Vercel Pro, либо внешний планировщик (например, cron-job.org).
- **Языки (раздел 70)**: тексты интерфейса не захардкожены в расчёте на локализацию, но переключение RU/KK/EN пока не реализовано — только сохраняется выбор языка в профиле.
- Разбиение серии повторений через "это и будущие" не переносит точное `count` оставшихся повторений на новую ветку (см. комментарий в `src/lib/database/recurrence.ts`).
- Поиск (раздел 36) по названию действий в локальном режиме регистронезависим для кириллицы (сравнение в JS); фильтр `search` в `/api/actions` (сейчас не используемый UI напрямую — используется отдельный `/api/search`) сравнивает через SQL LIKE и для кириллицы регистрозависим.

## Стек

- **Frontend/Backend**: Next.js 16 (App Router, Route Handlers), TypeScript, Tailwind CSS 4
- **База данных**: SQLite (`node:sqlite`, локально) или Supabase PostgreSQL + RLS (облако) — на выбор, без правок кода
- **Auth**: без авторизации в локальном режиме; Supabase Auth в облачном (email/password; Google/Apple OAuth — точка расширения)
- **Повторения**: RFC5545 RRULE (`rrule`)
- **Telegram**: Telegram Bot API напрямую (`fetch`, без тяжёлых SDK) — только облачный режим
- **Хостинг**: локально — свой компьютер; в облаке — Vercel + Vercel Cron

## Быстрый старт — локальный режим (рекомендуется для начала)

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000) — приложение сразу готово к работе,
без регистрации. База данных создастся автоматически в `.local-data/app.db`
(эта папка в `.gitignore`, не попадёт в git).

Чтобы начать с чистого листа — просто удалите папку `.local-data` и перезапустите `npm run dev`.

## Переход в облачный режим (когда понадобится Telegram или доступ с телефона)

### 1. Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. В SQL Editor выполните миграцию `supabase/migrations/0001_init.sql` целиком.
3. В Project Settings → API скопируйте `Project URL`, `anon public key` и `service_role key`.

### 2. Переменные окружения

```bash
cp .env.example .env.local
```

Заполните `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`
и перезапустите `npm run dev` — приложение автоматически переключится в облачный режим
(появится экран входа/регистрации). Остальные переменные (`TELEGRAM_*`, `CRON_SECRET`)
можно заполнить позже — без них приложение работает полностью, кроме Telegram и cron-рассылок.

### 3. Перенос уже накопленных данных

Пока вы работали локально, экспортируйте данные: Настройки → Данные → JSON (полная копия).
После регистрации в облачной версии: Настройки → Данные → выбрать файл → загрузить тот же JSON
(раздел «Импорт»). Действия перенесутся с проверкой на дубли; проекты/контакты/контекст
при таком переносе нужно будет создать заново — это ограничение текущей версии импорта.

## Настройка Telegram-бота (раздел 27, 61-62, 72-73 ТЗ, только облачный режим)

1. В Telegram напишите [@BotFather](https://t.me/BotFather), выполните `/newbot`, получите токен.
2. Заполните `.env.local`:
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather.
   - `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` — юзернейм бота без `@`.
   - `TELEGRAM_WEBHOOK_SECRET` — любая случайная строка.
3. После деплоя (публичный HTTPS-URL обязателен) зарегистрируйте webhook одним запросом:

```bash
curl -X POST "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://ваш-домен/api/telegram/webhook","secret_token":"<TELEGRAM_WEBHOOK_SECRET>"}'
```

4. В приложении: Настройки → Telegram → «Подключить Telegram» → подтвердить в боте командой `/start <код>` (код подставляется в ссылку автоматически).

## Cron-задачи (раздел 61, 77 ТЗ: не полагаться на открытый браузер, только облачный режим)

`vercel.json` уже описывает 4 задачи:

| Маршрут | Расписание | Назначение |
|---|---|---|
| `/api/cron/reminders` | каждую минуту | рассылка напоминаний, у которых наступило время |
| `/api/cron/morning-plan` | каждые 5 минут | утренний план в Telegram по времени пользователя |
| `/api/cron/evening-review` | каждые 5 минут | вечерний итог дня в Telegram |
| `/api/cron/overdue-check` | каждые 15 минут | пометка просроченных действий + уведомление |

Каждый маршрут защищён `CRON_SECRET` (см. `.env.example`). На Vercel Pro/Enterprise
эти расписания работают "из коробки". На Hobby-плане используйте внешний cron
(например, cron-job.org) с заголовком `Authorization: Bearer <CRON_SECRET>`.

## Структура проекта

```
src/
  app/            маршруты App Router: (auth) — вход/регистрация (только облако), (app) — основное приложение, api — все эндпоинты
  components/     UI по разделам (actions, calendar, timeline, projects, contacts, settings, layout, ui)
  lib/
    config.ts     определяет локальный/облачный режим (isLocalMode)
    local/        SQLite-реализация данных для локального режима (node:sqlite)
    database/     фасады: выбирают local/* или database/cloud/* по режиму — вызывающий код не знает, какой backend активен
    database/cloud/  Supabase-реализация (бизнес-логика поверх Postgres, без дублирования)
    supabase/     browser/server/admin клиенты + middleware (в локальном режиме — заглушки)
    recurrence/   построение и разворачивание RRULE
    reminders/    вычисление времени срабатывания напоминаний
    telegram/     Bot API клиент + форматирование сообщений
    notifications/service — единая точка отправки уведомлений по каналам
    export/       JSON/CSV/ICS экспорт и импорт (работает в обоих режимах)
    dates/        часовые пояса и календарные даты (раздел 66 ТЗ)
    ai/           точка расширения для AI-функций (раздел 63)
  types/          доменные типы
supabase/migrations/0001_init.sql   полная схема БД для облачного режима + RLS
vercel.json       расписание cron-задач (только облачный режим)
```

## Тестирование (раздел 80 ТЗ)

Автоматических тестов в поставке нет — ниже чек-лист для ручной проверки перед релизом:

- **Даты**: создать действие на сегодня/завтра/конец месяца/конец года/следующий год/29 февраля високосного года.
- **Перенос**: обычное действие, повторяющееся (this / this+future / all), с пересчётом напоминаний.
- **Напоминания**: одно, несколько, относительное, абсолютное, после переноса.
- **История**: создание → изменение → перенос → выполнение → отмена → архив → восстановление — все события видны в `/history`.
- **Telegram** (облачный режим): подключение, отключение, напоминание, утренний план, итог дня.
- **Мобильная версия**: 320px, 375px, 390px, 430px — нижняя навигация, без горизонтального скролла.
