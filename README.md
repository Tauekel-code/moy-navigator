# Моё личное расписание

Персональный цифровой диспетчер: календарь, расписание дня, задачи, контекст,
проекты, контакты, история и Telegram-уведомления. Реализовано по ТЗ
(`ТЗ_Мое личное расписание.docx`) на стеке **Next.js + TypeScript + Tailwind + Supabase**.

## Статус реализации

Все 6 этапов из раздела 83 ТЗ реализованы в объёме MVP+:

- **Этап 1 (ядро)** — авторизация, БД, действия, календарь (день/неделя/месяц/год), временная шкала, создание/редактирование, перенос (drag&drop + кнопка), статусы.
- **Этап 2 (интеллектуальная структура)** — контекст, проекты, контакты, дедлайны, результаты, повторения (RRULE + исключения серии), связанные действия.
- **Этап 3 (уведомления)** — reminders, Telegram-бот (подключение, напоминания, утренний план, вечерний итог), notification service, cron-обработчики.
- **Этап 4 (история)** — журнал изменений, архив (soft delete), глобальный поиск, фильтры, итоги дня.
- **Этап 5 (данные)** — экспорт JSON/CSV/ICS, импорт с проверкой дублей, offline-очередь — см. ограничения ниже.
- **Этап 6 (AI-ready)** — типы `ParsedActionDraft`, эвристический parser как пример контракта, точка расширения `aiParseNaturalLanguage`.

### Известные ограничения v1

- **Offline-очередь** (раздел 54) реализована архитектурно (API-слой изолирован от UI), но локальная очередь изменений на клиенте — не встроена; при потере сети запросы сейчас просто завершатся ошибкой с уведомлением, без автоматической синхронизации после восстановления связи.
- **Vercel Cron на бесплатном Hobby-плане** ограничивает cron-задачи одним запуском в сутки. Для напоминаний "по минутам" нужен либо Vercel Pro, либо внешний планировщик (например, cron-job.org), который дёргает `/api/cron/*` с заголовком `Authorization: Bearer $CRON_SECRET`.
- **Языки (раздел 70)**: тексты интерфейса не захардкожены в расчёте на локализацию (единая структура строк), но переключение RU/KK/EN пока не реализовано — только сохраняется выбор языка в профиле.
- Разбиение серии повторений через "это и будущие" не переносит точное `count` оставшихся повторений на новую ветку (см. комментарий в `src/lib/database/recurrence.ts`).

## Стек

- **Frontend/Backend**: Next.js 16 (App Router, Server Actions/Route Handlers), TypeScript, Tailwind CSS 4
- **База данных**: Supabase (PostgreSQL) + Row Level Security
- **Auth**: Supabase Auth (email/password; Google/Apple OAuth — точка расширения)
- **Повторения**: RFC5545 RRULE (`rrule`)
- **Telegram**: Telegram Bot API напрямую (`fetch`, без тяжёлых SDK)
- **Хостинг**: Vercel + Vercel Cron

## Быстрый старт (локально)

### 1. Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. В SQL Editor выполните миграцию `supabase/migrations/0001_init.sql` целиком.
3. В Project Settings → API скопируйте `Project URL`, `anon public key` и `service_role key`.

### 2. Переменные окружения

```bash
cp .env.example .env.local
```

Заполните `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`.
Остальные (`TELEGRAM_*`, `CRON_SECRET`) можно заполнить позже — без них приложение
работает полностью, кроме Telegram-уведомлений и автоматических cron-рассылок.

### 3. Установка и запуск

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000), зарегистрируйтесь — готово.

## Настройка Telegram-бота (раздел 27, 61-62, 72-73 ТЗ)

1. В Telegram напишите [@BotFather](https://t.me/BotFather), выполните `/newbot`, получите токен.
2. Заполните `.env.local`:
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather.
   - `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` — юзернейм бота без `@`.
   - `TELEGRAM_WEBHOOK_SECRET` — любая случайная строка.
3. После деплоя (публичный HTTPS-URL обязателен) зарегистрируйте webhook одним запросом:

```bash
curl -X POST "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://ваш-домен/api/telegram/webhook","secret_token":"<TELEGRAM_WEBHOOK_SECRET>"}'
```

4. В приложении: Настройки → Telegram → «Подключить Telegram» → подтвердить в боте командой `/start <код>` (код подставляется в ссылку автоматически).

## Cron-задачи (раздел 61, 77 ТЗ: не полагаться на открытый браузер)

`vercel.json` уже описывает 4 задачи:

| Маршрут | Расписание | Назначение |
|---|---|---|
| `/api/cron/reminders` | каждую минуту | рассылка напоминаний, у которых наступило время |
| `/api/cron/morning-plan` | каждые 5 минут | утренний план в Telegram по времени пользователя |
| `/api/cron/evening-review` | каждые 5 минут | вечерний итог дня в Telegram |
| `/api/cron/overdue-check` | каждые 15 минут | пометка просроченных действий + уведомление |

Каждый маршрут защищён `CRON_SECRET` (см. `.env.example`). На Vercel Pro/Enterprise
эти расписания работают "из коробки". На Hobby-плане используйте внешний cron
(например, cron-job.org) с заголовком `Authorization: Bearer <CRON_SECRET>`.

## Структура проекта

```
src/
  app/            маршруты App Router: (auth) — вход/регистрация, (app) — основное приложение, api — все эндпоинты
  components/     UI по разделам (actions, calendar, timeline, projects, contacts, settings, layout, ui)
  lib/
    database/     слой доступа к данным (бизнес-логика поверх Supabase, без дублирования)
    supabase/     browser/server/admin клиенты + middleware
    recurrence/   построение и разворачивание RRULE
    reminders/    вычисление времени срабатывания напоминаний
    telegram/     Bot API клиент + форматирование сообщений
    notifications/service — единая точка отправки уведомлений по каналам
    export/       JSON/CSV/ICS экспорт и импорт
    dates/        часовые пояса и календарные даты (раздел 66 ТЗ)
    ai/           точка расширения для AI-функций (раздел 63)
  types/          доменные типы
supabase/migrations/0001_init.sql   полная схема БД + RLS
vercel.json       расписание cron-задач
```

## Тестирование (раздел 80 ТЗ)

Автоматических тестов в поставке нет — ниже чек-лист для ручной проверки перед релизом:

- **Даты**: создать действие на сегодня/завтра/конец месяца/конец года/следующий год/29 февраля високосного года.
- **Перенос**: обычное действие, повторяющееся (this / this+future / all), с пересчётом напоминаний.
- **Напоминания**: одно, несколько, относительное, абсолютное, после переноса.
- **История**: создание → изменение → перенос → выполнение → отмена → архив → восстановление — все события видны в `/history`.
- **Telegram**: подключение, отключение, напоминание, утренний план, итог дня.
- **Мобильная версия**: 320px, 375px, 390px, 430px — нижняя навигация, без горизонтального скролла.
